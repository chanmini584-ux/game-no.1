## 3. 추천안 상세 — 《윗집 (THE FLOOR ABOVE)》

### 3.1 기본 설정
- **태그라인**: "최상층인데, 윗집에서 소리가 난다." / "You live on the top floor. So who's upstairs?"
- **배경**: 가상의 2001년식 25층 구축 아파트 '솔빛마을 3단지 307동'. 11월 하룻밤, 새벽 02:14부터 06:40까지.
  - 공간: 2501호, 복도(센서등), 엘리베이터, 계단실, 24층, 1층 경비실·관리사무소, 지하주차장, 분리수거장, 옥상, 그리고 밤에만 생기는 26층
- **주인공 한지우 (28)**: 밤낮이 바뀐 자막 번역가. 엄마의 전화도 받지 않는 '대답하지 않는 사람'이다. 이 사람이 '대답하는 사람'으로 바뀌는 것이 이야기의 축이다.
- **주제**: 26층은 아무도 대답해 주지 않은 노크들이 쌓여 생긴 층이다. 괴물을 만드는 것은 무관심이다.
  - 고독사, 층간소음 같은 한국 일상 소재를 쓰되 실제 사건은 재현하지 않는다.
  - 피해자를 괴물로만 소비하지 않는 톤을 유지한다.

### 3.2 시그니처 시스템: 「한 번 더」 노크 응답
빗자루로 천장이나 바닥을 1~9회 두드리면 건물이 소리로 대답한다.

| 응답 | 의미 |
|---|---|
| 같은 횟수 | 에코. 상대가 듣고 있다(안전) |
| **횟수 +1** | 그것이 **같은 방 안에** 있다. 옷장이나 문 뒤에서 소리가 나고, 3초 안에 방을 나가야 한다 |
| 위에서 옴 | 그것 |
| 아래에서 옴 | 사람. 24층 할머니는 '살아 있다'는 뜻으로 세 번 두드린다. 그것은 여기에 한 번을 더해 흉내 낸다(3 → 4) |

수첩의 '노크 사전'에 응답이 자동으로 기록되고, 노크 퍼즐은 이 사전을 읽어서 푼다.

**스트리머 클립 포인트**
1. 채팅창이 "3번!"을 외치는데 네 번째 소리가 옷장에서 난다.
2. 할머니의 세 번이 끊긴 정적.
3. 마지막 반전: 평생 천장만 두드리던 플레이어가 빗자루를 뒤집어 **바닥에 대답한다**.
4. 게임오버 화면이 **'층간소음 민원 접수증'** 형식이다(처리 결과: 확인 불가 / 비고: 윗집 없음). 밈으로 퍼지기 쉽다.

### 3.3 구조와 규모
| 항목 | 내용 |
|---|---|
| 챕터 | Ch1 2501호 → Ch2 복도·엘리베이터 → Ch3 1층·지하(할머니의 노크가 끊김) → Ch4 단지 야외·옥상 → Ch5 26층 |
| 엔딩 4종 | 진엔딩 '대답' / 보통 '이사' / 배드 '26층' / 배드 '접수 완료'. 게임오버는 접수증 변형 6종 |
| 맵 | 24개 (아파트는 층마다 평면이 같다는 점을 이용해 고유 12개 + 변형 12개) |
| 캐릭터 그림 | 스프라이트 시트 14종, 초상화 18장, 이벤트 CG 12장 |
| 퍼즐·추격 | 퍼즐 12개(노크 퍼즐 5), 추격 8회(합계 약 20분) |
| 텍스트 | 한국어 대사 약 3만 자 + 문서·쪽지 40종(약 1만 자). 영어·일본어 동시 출시 |
| 사운드 | 효과음 약 120종(노크 재질별 12종 포함), 앰비언트 BGM 7곡, 성우 3역(인터폰, 엄마, 안내방송) |

### 3.4 심사 지적에 따른 보완 (다른 안의 장점 이식)
| 약점 | 보완 |
|---|---|
| 2회차 동기 부족 | C안의 규칙 섞기를 가져와 **'다른 밤' 모드**를 넣는다. 회차마다 26층의 노크 신호 체계가 바뀐다 |
| 캐릭터 매력 부족 | 할머니와 '한 번 더'의 디자인을 굿즈·팬아트가 가능한 상징으로 키운다. 게임오버 접수증 이미지를 저장·공유하는 버튼을 단다(D안) |
| 청각 의존 | 소리 시각화 모드(자막 "[쿵×3, 위]", 화면 가장자리 진동)를 처음부터 기본 설계에 넣는다. 접근성과 무음 숏폼 클립 모두에 필요하다 |
| 퍼즐 공정성 | 모든 퍼즐이 정답 하나로만 풀리는지 자동 검사기로 확인한다(B안 방식, Haiku 담당) |
| 반복 피로 | 죽으면 구간 시작점에서 바로 재개한다(D안) |
| 시장 반응 불확실 | Look Outside 경로를 따른다. **Ch1 프로토타입을 2개월 안에 무료로 먼저 공개**해 훅을 검증한다(9절 결정 #5) |


### 3.5 프로듀서 지시 반영 (2026-10-12): 보이는 귀신 + 아오오니식 추격
- 원안의 "보이지 않는 윗집"을 **눈에 보이는 메인 귀신이 직접 쫓아오는 추격 공포**로 바꾼다.
  - 메인 귀신은 게임의 얼굴이 되는 상징적 존재로 만든다.
  - 서브 귀신 4명(26층 거주자)은 각자 다른 추격 규칙을 가진다.
- **노크 시스템은 귀신 탐지 장치**로 바뀐다. 응답으로 귀신의 위치와 상태를 알아내고, '한 번 더'가 오면 같은 방에 있다는 뜻이며 곧 추격이 시작된다. 다른 아오오니류 게임과의 차별점이다.
- 추격은 8회에서 12~15회로 늘린다. 문과 층을 넘어 따라오고, 숨을 곳이 있으며, 잡히면 추격 시작점에서 바로 재개한다.
- 영향: 메인 귀신 스프라이트 애니메이션이 늘어 아트 비용이 소폭 오른다. 추격 AI(층·문 이동 경로 탐색)는 Opus가 담당한다.
- **추가 지시 (같은 날)**: 윗집은 **백룸처럼 갑자기 생긴, 원래 없던 다락방**이다. 올라가면 내려가는 문이 사라지고, 귀신을 피해 도망치며 **내려가는 문을 찾는 것**이 게임의 목표다.
  - 다락방 너머는 아파트를 닮았지만 틀린 공간이다. 올라갈수록 실제 아래층(로비, 주차장 등)의 뒤틀린 복제본이 나온다.
  - 이제 지우가 "윗집 사람"이고, 바닥 아래가 현실이다. 마지막 반전인 바닥 노크가 곧 탈출의 열쇠가 된다.
- 상세 지시서: `docs/story/brief_v1.md` (v1.1)

## 5. 기술
- **엔진: Godot 4.6 (2D)**. 이미 이 환경에 설치되어 있고 화면 렌더링 검증까지 확인했다.
  - 해상도 480×270, 32px 타일, Light2D 조명, 공간 오디오(AudioStreamPlayer2D + 버스 필터)
- 쯔꾸르의 내장 이벤트 시스템이 없으므로 **이벤트·대화·플래그 엔진을 직접 만든다**. M1에서 검증하고, 실패하면 RPG Maker MZ로 갈아탈지 판단한다.
- 맵은 Tiled 또는 Godot TileMap으로 만들고, 같은 평면을 여러 층에 재사용하는 자동화 스크립트를 둔다.
- 데이터 기반 설계: 대사, 퍼즐, 노크 사전, 엔딩 조건은 JSON/CSV로 관리한다(번역과 자동 검사 용이).
